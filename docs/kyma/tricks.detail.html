1. Executive Summary

The KymaGrid Battery Management System (BMS) is a sophisticated, software-defined energy control platform built on the Regno universal telemetry infrastructure. It orchestrates industrial battery energy storage systems through a dual-inverter topology that physically separates charging (OnGrid PCS connected to utility grid) and discharging (OffGrid PCS connected to load) power paths. The system's architecture features a two-layer software stack: a Model layer responsible for stateflow management, decision logic, safety enforcement, and real-time setpoint generation; and a Dashboard platform serving as the supervisory "brain" that orchestrates subsystem interactions, handles fault tolerance, streams data to Regno databases, and provides remote monitoring capabilities. Originally proven at the Chippewa deployment, the system was enhanced at ZnT with a re-architected communication layer enabling hardware-independent deployment, eliminating laptop dependencies, and adding independent OnGrid/OffGrid operation modes. Field testing has validated the system's ability to handle steady loads of 35-45 kW, absorb inrush events up to 230 kW, perform overnight trickle charging at 10 kW continuous, and sustain real plant operations for extended periods in fully islanded (off-grid) mode.

Dual-Inverter Topology Advantage

Unlike conventional single-path BESS where the same inverters handle both charging and discharging, KymaGrid's dual-inverter architecture physically separates these functions. This enables:

  • Simultaneous charge/discharge: Charge from grid while powering plant
  • Complete grid isolation: Plant runs on battery during grid outages
  • Independent operation: OnGrid can enter standby while OffGrid continues supplying load
  • Maintenance flexibility: Service one path without full shutdown

3. Software Architecture

The KymaGrid software stack consists of two primary layers working in concert to manage the battery energy storage system:

Dashboard Monitoring & Control Platform

Role: The supervisory "brain" that oversees and coordinates all subsystems

Core Functions:

  • Communicates with battery and PCS in real time
  • Collects and streams system data to Regno databases
  • Provides detailed diagnostics, historical analysis, and fault tracing
  • Handles fault tolerance by monitoring subsystem health
  • Automatically manages recovery procedures where possible
  • Orchestrates interactions between core, battery, PCS, and Model
  • Ensures safe and optimized operation across all conditions

User Interface:

  • Visualization of system status in real time
  • Error diagnostics and alert management
  • Direct control inputs for manual intervention
  • Engineering monitoring and troubleshooting tools

Model (Software Control Layer)

Role: The specialized "organ" responsible for operational decisions and flow control

Responsibilities:

  • Stateflow Management: Manages state machine transitions between operational modes
  • Decision Logic: Determines optimal charge/discharge strategies
  • Safety Enforcement: Validates all operations against safety constraints
  • Setpoint Generation: Produces real-time setpoints for PCS control
  • Command Propagation: Sends charge/discharge commands to PCS units

Evolution:

  • Original (Chippewa): Ran on laptop, limited portability
  • Enhanced (ZnT): Decoupled communication layer, hardware-independent
  • Current: Integrated into Brain as standalone service

3.1 Blackbox "Brain" Configuration

OnLogic Hardware Platform

The Brain is a self-contained control unit consisting of:

  • Operations Machine: OnLogic industrial hardware
  • Database: 1x database instance for data storage and retrieval
  • Software Stack: 1x complete software stack including Dashboard and Model
  • UPS: Uninterruptible power supply for continuous operation during power transitions
  • Network Stack: Configured for local and remote connectivity
  • Starlink Module: Satellite connectivity for remote access

7. Integration Topologies

KymaGrid supports multiple integration architectures to accommodate diverse site requirements and scaling needs.

7.1 Parallel Integration

Common DC Rail, Common AC Rail

Standard configuration where all DC blocks connect to a shared DC bus, and all inverter skids (4 MW peak each) connect to a common 4.16 kVAC AC rail. Suitable for:

  • Grid-tied applications with bidirectional power flow
  • Sites requiring maximum flexibility in charge/discharge paths
  • Integration with solar, BESS, and gas gensets on common AC bus

7.2 Split Integration (ZnT Configuration)

Common DC Rail, Separate Charging/Discharge AC Rails

The configuration deployed at ZnT, featuring two separate AC rails for charging and discharging operations:

  • Charging AC Rail: Connected to grid/generator for battery charging
  • Discharge AC Rail: Connected to plant load for power delivery
  • Advantage: Enables independent OnGrid/OffGrid operation
  • Use Case: Industrial loads requiring grid isolation capability

7.3 HV Group Integration

DC Groups to Single PCS, All PCS in Parallel

Large-scale configuration for multi-MW deployments:

  • Multiple KYMA SG (Storage Groups) with dedicated SKID and CORA units
  • DC blocks grouped and connected to individual PCS units
  • All PCS units operate in parallel on AC side
  • Scalable from single group to 3+ groups (shown: KYMA SG 1, 2, 3)

8. The Tricks - Complete Capabilities

A comprehensive catalog of KymaGrid BMS capabilities that differentiate it from conventional battery management systems:

🔌

Hardware-Independent Deployment

Communication layer re-architected to decouple from physical hardware requirements. Model runs as standalone service integrated into any site's software stack, enabling faster, more repeatable, hardware-agnostic deployments across different battery chemistries and PCS configurations.

🔄

Independent OnGrid/OffGrid Operation

OnGrid and OffGrid PCS operate completely independently. When generator is turned off, OnGrid PCS enters standby while OffGrid PCS continues discharging to plant without interruption. Enables simultaneous charging and discharging, or complete grid isolation during outages.

⚡

230 kW Inrush Event Handling

System handles occasional inrush events up to 230 kW while maintaining stability. Short power bursts (~0.06 kWh each) absorbed without failure, demonstrating robustness for industrial applications with variable demand profiles and motor starting transients.

🌙

Overnight Trickle Charging

Intelligent overnight charging at 10 kW continuous from ~18:00 to 09:30, maintaining battery SOC at optimal levels (68% by morning). Gentle charging approach extends battery cycle life while ensuring full capacity for peak demand periods during daytime operations.

📱

Remote Access & Control

Full supervisory control via Starlink connectivity for Brain, battery, and PCS. Enables secure remote monitoring, deployment of tested software updates, and remote command issuance—reducing on-site intervention needs and enabling centralized multi-site management.

🛡

Fault Tolerance Orchestration

Dashboard monitors subsystem health and automatically manages recovery procedures. Coordinates interactions between core systems, battery, PCS, and Model to ensure safe and optimized operation even during unexpected conditions and component failures.

📊

Real-Time Setpoint Generation

Model layer continuously generates real-time setpoints (charge/discharge commands) and propagates them to PCS. Stateflow management ensures optimal power flow decisions based on current system state, load demands, SOC levels, and safety constraints.

🗄

Regno Data Streaming

All system data collected and streamed to Regno databases for detailed diagnostics, historical analysis, and fault tracing. INSIGHT platform provides visualization of system status, error diagnostics, and engineering intervention capabilities.

🏭

Proven Off-Grid Plant Operation

Demonstrated fully off-grid operation at ZnT—plant ran for 2+ continuous hours powered solely by battery with no grid connection. System sustained real plant loads (35-45 kW steady, 230 kW peaks) validating industrial-scale islanded operation capability.

🔧

PCS Frequency Stabilization Tuning

PCS firmware upgraded for fine-grained control over synchronization parameters. Tuned startup timing accommodates generator frequency overshoot during initial sync, achieving stable operation and successful battery charging from generator sources.

📦

Blackbox "Brain" Architecture

Self-contained control unit on OnLogic industrial hardware with database, software stack, and UPS backup. Eliminates external laptop dependencies and provides scalable foundation for managing deployments across multiple sites with consistent configuration.

🔀

Flexible Integration Topologies

Supports multiple architectures: Parallel Integration (common DC/AC rails), Split Integration (separate charging/discharge AC rails), and HV Group Integration (DC groups to single PCS). Architectural flexibility adapts to diverse site requirements and scaling needs.

🧠

Two-Layer Software Architecture

Dashboard serves as supervisory "brain" for coordination and monitoring, while Model acts as specialized "organ" for operational decisions. Clear separation of concerns enables independent development, testing, and troubleshooting of each layer.

🚀

Jump Start Capability

System can be initialized from external source (BESS 101-104 + PCS-1), after which PCS-1 generates AUX power for all remaining units. Jump start source can be removed after initialization. Alternative path through CORAs also available.

💻

Visual State Verification

During deployment, Model can run on laptop for visual verification of state transitions and logical flows in real-time. Provides troubleshooting flexibility and confirmation of model operation during integration before migration to Brain hardware.

Scalable Multi-Site Foundation

9. Issues & Resolutions

Documentation of technical challenges encountered during ZnT deployment and their solutions:

9.1 Phase 2 Issues

Issue: PCS Installation Order

Problem: At Chippewa, PCS1=OffGrid and PCS2=OnGrid. At ZnT, installation was reversed: PCS1=OnGrid and PCS2=OffGrid.

Impact: Inconsistent terminology (OnGrid/GridTie/Inverter1 vs OffGrid/GridForm/Inverter2) caused confusion, leading to unnecessary model rollbacks and misdiagnosis.

Resolution: Architecture is actually agnostic to ordering; standardized terminology documentation resolved confusion.

Issue: Generator Specification

Problem: ZnT was outfitted with 125 kW generator vs Chippewa's 250 kW.

Impact: Undersized generator could not handle PCS demand, repeatedly tripping offline.

Resolution: Field expert confirmed 250 kW - 1 MW required. Generator upgraded to correct specification.

Issue: PCS Synchronization Timing

Problem: PCS startup failed due to overly strict synchronization timing.

Impact: Normal generator frequency overshoot exceeded PCS timeout, incorrectly concluding no power available.

Resolution: PCS firmware upgraded to allow fine-grained control over synchronization parameters. Settings tuned for generator behavior.

9.2 Phase 4 Issues

Issue: Plant Switch Power Loss

Problem: When plant switch thrown to draw battery power, all power lost including Brain and hardware.

Impact: System control lost during critical transition.

Resolution (5-10 min): UPS found incorrectly connected. Brain temporarily powered via external generator. UPS reconnected correctly for future validation.

Issue: Model Connectivity Loss

Problem: Model running on laptop lost power/connectivity to battery.

Impact: Battery entered communication fault state, shutting down plant power.

Resolution (10-15 min): Laptop connected to reliable power source. Issue fully eliminated in Phase 5 when Model migrated to Brain hardware.

9.3 Phase 6 Issues

Issue: Starlink Performance

Problem: Residential Starlink lacks fixed IP address. Reverse VPN strategy introduces performance hit through multiple translation layers.

Impact: Cannot guarantee 100% remote access uptime (local operation unaffected).

Proposed Solution: Purchase business Starlink account with static IP for required flexibility.
